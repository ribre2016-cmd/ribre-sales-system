# Phase 7 実測の手順（利用者にお願いする作業）

作成: 2026-08-04

3視点レビューで**設計とモックは合格**したが、A の条件として
**未確認事項 P7-A〜D の実測**が残っている。実測にはMFの操作が要るため、
利用者（佐渡さま）にお願いする作業をここにまとめる。

⚠ **P7-B だけは本番の帳簿に書き込む。** 明示的な許可をいただくまで実行しない。

## 作業1: MF連携のやり直し（5分・これが最優先）

**なぜ必要か**: 価値が最も高い**⑨月次チェック**が `report.read` スコープ1つに懸かっている。
再連携1回で **P7-A・P7-C・P7-D がまとめて確認できる**。

追加するスコープ（`api/mf/_lib/mf-client.js` の `MF_SCOPE`）:

```
mfc/accounting/report.read              ← ⑨月次チェック（推移表・試算表）
mfc/accounting/offices.read             ← 会計年度設定（3/1〜2/28をハードコードしなくて済む）
mfc/accounting/connected_account.read   ← 口座ごとのデータ到達状況
mfc/accounting/transaction.write        ← 現金払い（作ると決まった場合のみ使う）
mfc/accounting/trade_partners.write     ← 取引先マスタ（優先度低）
```

**手順**:

1. こちらでコードにスコープを追加してデプロイする（利用者の作業なし）
2. 利用者が本番の画面から **MF連携をやり直す**（既存の連携開始ボタンから）
3. 完了したら教えていただく

⚠ **既存の機能は影響を受けない**（今のトークンのスコープはそのまま有効）。
⚠ **再連携は1回で済ませたいので、5つまとめて追加する。**

## 作業3: ⑦現金払いを作るかどうかの確認（利用者に伺うこと）

`CLAUDE.md` に既に次の取り決めがある:

> 現金レシート → **MFクラウド経費**のスマホアプリ（このシステムの守備範囲外）

**伺いたいこと**:

1. 現金レシートは、いまMFクラウド経費アプリで処理できていますか？
2. できているなら **⑦は作りません**（同じことを2経路で作ると現場が迷うため）
3. できていない場合、その理由は何ですか（アプリを使っていない・連携していない等）
   → 理由によっては **MF経費アプリの設定を直すほうが正しい**かもしれません

⚠ **この確認が先。** 作らないと決まれば P7-C の実測自体が不要になる。

## 作業4: P7-B の実測（★明示的な許可が必要★）

**⑨⑩や質問と回答には不要。★E（登録の取り消し）を作る場合にだけ必要。**

**確認すること**: MFの仕訳を削除したとき、元の明細（transaction）の仕訳化ステータスが
`registered` から `none`（未仕訳）に戻るか。

**なぜ許可が必要か**: 確かめるには **本番の帳簿に仕訳を1件作って、それを消す**しかない。
OpenAPI仕様には記載がなく、推測では判断できない。

**提案する手順**（許可をいただけた場合）:

1. 金額の小さい未仕訳明細を1件選ぶ（利用者に選んでいただく）
2. その明細から仕訳を作る（証憑は**添付しない**）
3. 明細のステータスが `registered` になることを確認
4. その仕訳を `DELETE /journals/{id}` で削除する
5. 明細のステータスが `none` に戻るか確認する
6. 戻った場合 → その明細は元どおり未仕訳。**帳簿への影響なし**
7. 戻らなかった場合 → その明細は「仕訳済みだが仕訳が無い」状態になる。
   **MFの画面から手当てが必要**（この状態になるリスクがあることを承知いただく必要がある）

**結果による分岐**:

- 戻る → ★E（登録の取り消し）を作る。新人の最大の不安が解消される
- 戻らない → **★Eを作らない**。「MFの仕訳帳から削除してください」の案内に戻す

⚠ **許可がいただけない場合も、★Eを作らないだけで他は全部進められる。**
