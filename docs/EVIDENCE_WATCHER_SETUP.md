# 証憑フォルダ監視（常駐ウォッチャー） セットアップ手順

パソコンの決まったフォルダに証憑（領収書・請求書）のPDFや画像を置いておくだけで、
**ブラウザを閉じていても**自動でOCRされ、`mf-evidence.html` の台帳に
「承認待ち」として翌朝には並んでいる仕組みです。

**MFクラウドBoxへの送信は今まで通り承認制です。このウォッチャーが自動で
送信することは絶対にありません。** 台帳で内容を確認し、「MFへ送信」ボタンを
押した証憑だけが実際にMFへ送信されます（メール取込と同じ仕組みです。
`api/mf/ingest-mail.js` の承認制の実装を参照）。

売上のCSVはこの仕組みの対象外です。売上はどのみち画面で確認する必要があるため、
常駐化のメリットは証憑（OCR）に限られます。

## 1. 事前準備: MAIL_INGEST_SECRETの値を確認する

すでにメール取込（`docs/MAIL_INGEST_SETUP.md`）を設定済みなら、その時と同じ値を使います。
未確認の場合は次の場所で確認できます。

1. Vercelのダッシュボードを開く
2. 対象プロジェクト（ribre-sales-system） → **Settings** → **Environment Variables**
3. `MAIL_INGEST_SECRET` の値をコピーしておく（値は「Reveal」等で表示できます）

この値は次の手順3で入力するもので、他人に見せないよう扱ってください。

## 2. インストーラーの実行

1. `tools\evidence-watcher-install.ps1` を右クリックし、「PowerShellで実行」を選ぶ
   （表示されない場合は、コマンドラインから以下を実行してください）
   ```
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\evidence-watcher-install.ps1
   ```
2. 監視フォルダを聞かれます。**証憑専用の小さなフォルダ**をおすすめします
   （Enterキーだけ押すと「ダウンロード」フォルダが使われますが、OCRのAPI利用料が
   新しいファイルごとにかかるため、大きな/雑多なフォルダを指定すると余計な課金が
   発生する可能性があります）
3. 取込先URLを聞かれます。通常はEnterキーで既定値（本番URL）のままでかまいません
4. `MAIL_INGEST_SECRET` の値の入力を求められます。**入力中は画面に何も表示されません**
   （パスワード入力と同じ扱いです。貼り付けは通常どおり使えます）
5. 完了すると、タスクスケジューラに「RIBRE証憑ウォッチャー」というタスクが登録され、
   **30分おき**に自動実行されるようになります

再実行しても安全です（既存の設定・タスクを一度削除してから登録し直します）。

## 3. 動作確認

1. 監視フォルダに、PDFまたは画像(PNG/JPEG)の証憑ファイルを1つ置く
2. 次のコマンドで手動実行し、正常終了（メッセージが出ずコマンドが終わる）を確認する
   ```
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\evidence-watcher.ps1
   ```
3. https://ribre-sales-system.vercel.app/mf-evidence.html を開き、
   台帳に置いたファイルが「送信前（承認待ち）」の状態で追加されていることを確認する
4. うまくいかない場合は、次のログファイルを確認する
   （タブ区切り: 日時・ファイル名・結果・詳細）
   ```
   %APPDATA%\ribre-evidence-watcher\watcher.log
   ```

30分おきの自動実行を待たずにすぐ試したいときは、手順2のコマンドを都度手動実行してください。

## 4. ファイルサイズの上限（3MB）

メール取込（Apps Script）と同じ理由で、**3MBを超えるファイルは送信されません**
（Vercelのサーバーレス関数はリクエストボディが約4.5MBを超えると失敗するため、
base64化で約4/3に膨張することを見込んで実ファイル3MBを上限にしています）。

- 3MB超のファイルは1回だけログに記録され、以後は毎回チェックせずスキップされます
  （容量の大きいファイルが監視フォルダに残っていても、無駄なアクセスは起きません）
- 3MBを超える証憑は、`mf-evidence.html` を開いて手動で貼り付け/ドラッグ＆ドロップして
  登録してください（同画面のアップロード上限も同じ理由で3MBのため、それでも超える
  場合はPDFの解像度を下げる・分割するなどして圧縮してから登録してください）

## 5. 重複登録の心配について

サーバー側（`api/mf/ingest-mail.js`）が**ファイルの中身（バイト列）のハッシュ**で
重複を判定するため、メール取込と同じ証憑をこのウォッチャーでも取り込んでしまっても、
二重に台帳へ登録されることはありません（2つ目以降は「重複」として扱われるだけです）。

このウォッチャー自身も送信済みファイルを記憶しており（`sent.json`）、同じファイルを
毎回サーバーへ送り直すことはしません。万が一この記憶ファイルが壊れたり消えたりしても、
上記のサーバー側の重複排除があるため安全です（再送されても「重複」と判定されるだけで、
台帳が二重に増えることはありません）。

## 6. 止めたいとき（ロールバック）

タスクだけを削除し、設定やこれまでの送信記録は残す場合:

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\evidence-watcher-install.ps1 -Uninstall
```

タスクスケジューラの「タスクスケジューラ ライブラリ」から「RIBRE証憑ウォッチャー」を
手動で削除しても構いません。

なお、`MAIL_INGEST_SECRET` をVercel側で未設定に戻す/削除すると、
`/api/mf/ingest-mail` 自体が503を返すようになり、メール取込・このウォッチャー
どちらからの取込も止まります（二重の安全策です）。

## 7. 各ファイルの場所（参考）

| 内容 | 場所 |
|---|---|
| 設定（監視フォルダ・シークレット等） | `%APPDATA%\ribre-evidence-watcher\config.json` |
| 送信済みファイルの記録 | `%APPDATA%\ribre-evidence-watcher\sent.json` |
| 実行ログ（1MB超で自動ローテーション） | `%APPDATA%\ribre-evidence-watcher\watcher.log` |

## 8. 常駐タスクの動作条件について

タスクスケジューラの仕組み上、このウォッチャーは**PCの電源が入っていて、
設定したユーザーでログインしている間だけ**動作します。スリープ中・シャットダウン中・
ログオフ中は動きません。これは意図した仕様です（次にログインした時にまとめて
処理されます）。24時間365日動かし続けたい場合は別途サーバーでの常時稼働が必要ですが、
現状はその必要はないと判断しています。
